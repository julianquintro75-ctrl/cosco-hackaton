Arquitectura de cosco-hackaton

Recomendador de proveedores para transporte terrestre en Colombia. Cinco capas con una dependencia en un solo sentido: los clientes llaman a la API, la API a un motor de decisión, el motor al núcleo estadístico y este a los datos. Datos sintéticos.

Cómo crecer sin reescribir

Nuevo frontend

Consume la API HTTP (/recomendar, /decision…). Para que la UI actual haga lo mismo falta reemplazar el import app.api por un cliente httpx usando COSCO_API_URL.

Otro servicio backend

Se agrega como un servicio más en docker-compose.yml, en la red cosco, y la API lo llama por HTTP. Los contratos pydantic definen los mensajes.

Otro motor de decisión

Implementa MotorDecision (contratos/contracts.py). Jev y el LLM ya tienen ese lugar; siguen sin medirse.

Nueva base de datos

Hoy engine/datos.py usa sqlite3 directo. Antes de cambiar de base hay que introducir una interfaz de repositorio; el esquema vive en db/schema.sql.
